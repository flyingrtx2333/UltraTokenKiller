# Mac 原生通信、用量采集与输入压缩复验

环境：macOS arm64、Python 3.11.16、Codex 0.153.4、现有订阅、gpt-5.6-luna。延续同一本请求账本，本轮从 23/40 到 **40/40**，共使用 17 次；没有增加上限或切换 API。最终服务已停止，隔离目录中没有遗留 PID 文件。

## 已实现的修复

### 本地通信

Unix 平台的同一个服务进程同时监听 HTTP 和私有 Unix socket，工具压缩、MCP 恢复、输入压缩共用同一个内存仓库。socket 位于按用户隔离的 0700 目录，文件权限为 0600；拒绝覆盖普通文件和活跃 socket，正常退出时清理。Windows 保留 HTTP。

Mac 隔离验收使用工作区文件权限，启用 Codex 网络代理，仅白名单放行 UTK 的具体 socket，不允许任何域名。不能只设置 `network.enabled=true`：必须同时启用代理才能执行限制。该行为依据 [Codex 权限文档](https://learn.chatgpt.com/docs/permissions)，并由当前实机验证。

预检确认：UTK 压缩与恢复成功；直接 TCP、其他 Unix socket 被系统拒绝；通过 Codex 网络代理访问未授权地址返回 403。未通过预检不提交模型请求。

此配置目前由隔离验收入口使用；日常 `utk codex` 对用户既有 legacy sandbox/profile 设置的兼容合并仍未完成，不能宣称所有默认禁网配置均已自动适配。

### 提供商实际用量

实测上游返回 SSE 内容，但没有 SSE 的内容类型标记。原解析器把整段流作为单个 JSON 解析，漏记 usage。现在根据明确的 SSE 字段前缀识别流，支持跨块前缀，保留转发字节不变；普通 JSON 不误判。新增观测信息只记录计数和状态，不记录正文。

修正后最后两轮共 8 次提供商响应均记录到 usage。客户端汇总单列为 `client_reported_usage`，不重复合并进代理用量，也不把缺失值当零。

### 输入协议覆盖

新增 Responses 的 `function_call_output` / `custom_tool_call_output` 结构化文本数组、Chat 工具内容数组、Anthropic 工具结果内容数组。仅压缩其中的文本，保留调用 ID、顺序、图像、音频、加密内容和用户问题。测试验证原文可找回、输入对象不被修改、重复处理后的历史内容稳定。
