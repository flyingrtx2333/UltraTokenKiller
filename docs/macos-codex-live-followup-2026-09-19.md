## 故障与修正

此前累计 19/20 次时，真实任务没有工具压缩记录，MCP 查询不可用，源码未修改。旧记录将问题归因于 matcher 未命中，证据不足，现更正为未证实假设。

本轮在 Codex 自身的 macOS 工作区沙箱连接本机端口，复现 `PermissionError: Operation not permitted`。默认网络限制阻断工具进程到 UTK 的压缩和统计请求。

验收使用临时 `utk_acceptance` 权限配置，继承 `:workspace` 的文件限制并启用网络。它只作用于验收进程，不写入用户配置。**该配置允许网络访问，不是仅放行回环端口；日常默认禁网沙箱的自动接入仍待解决。**

其他修正：

- Mac 也必须先通过沙箱内工具压缩、统计与原文恢复检查，失败时不提交模型请求。
- 原文查询上限从 16,000 改为 32,000 字符，覆盖带路径和行号的完整搜索结果。
- 钩子只改写已知命令工具；未知工具即使有 command 字段也不改写。Codex 0.153.4 要求 `permissionDecision=allow` 才采用 updatedInput，因此保留该字段并限制可改写命令与参数。
- 新增显式提高授权总上限的入口，保留已用次数，重复操作不再次增加额度；普通请求不能扩大上限。
- 后续报告名称增加唯一时间戳，避免零请求启动失败覆盖此前同计数报告。
